# ОБЗВОН v7.11 — система обзвона

Система проведения обзвона с проверкой внимательности участника: самостоятельный
старт обзвона без куратора, испытания во время сессии, метрики в реальном времени
и итоговый вердикт.

> **Внутренние механизмы контроля, детали их реализации, пороги и настройки
> в открытых материалах не описываются и не публикуются.**

## Возможности
- **Два новых вида испытаний (v7.0)**: **«Счёт»** — посчитать нужные символы
  среди других, и **«Слово»** — кликнуть по слову, которое написано **цветом**
  (зеркальный Струп: тянет ответить цветом, а не словом).
- **Режимы обзвона (v7.0)**: «Обычный», «Спринт» (короткие окна, чаще),
  «Экзамен» (только сложные виды), «Тренировка» (простые виды, мягкие окна).
  Переключатель — в пульте куратора.
- **Профили участников и оценка доверия (v7.0)**: система помнит анонимные
  профили устройств (сколько обзвонов, средняя концентрация, типичная реакция)
  и считает **доверие 0–100**. Это отпечаток устройства, а не человек.
- **Тревожный сигнал (v7.0)**: сильное нарушение во время обзвона — яркая
  плашка и звук в админке, а через сборщик событие уходит в **Telegram**.
- **HTML-отчёт для руководства (v7.0)**: одна страница со сводкой по всем
  обзвонам (средняя концентрация, зачёты, таблица) — открыть, распечатать,
  отправить. Плюс кнопка «Все данные» — выгрузка всего в один JSON.
- **Настройки интерфейса (v7.0)**: плотность (обычная/плотная), крупные
  кнопки ответа (для телефона), громкость звуков. Сохраняются в браузере.
- **Пример испытания (v7.0)**: тех. администратор может посмотреть, как
  выглядит любое задание, не начиная обзвон.
- **Статистика в цифрах (v6.1)**: админ видит, сколько раз открывали сайт,
  сколько калибровок начали и прошли, сколько обзвонов начали и закончили.
  Счётчики живут в браузере; чтобы узнать, сколько людей заходило **с разных
  устройств**, включите сборщик: `tools/collect.php` (или `tools/collector.js`)
  кладётся рядом с сайтом, адрес — в `config.json`. Данные анонимные: только
  случайный id устройства, тип события и время.
- **Калибровка починена (v6.1)**: она стала проходимой — окно ответа на каждое
  испытание теперь не меньше минимума, «Память» требует столько же символов,
  сколько в сеансе, а провал **не стирает прогресс** (повторяется то же
  испытание, после трёх попыток калибровка идёт дальше) и **не штрафует**
  «читомеряк». Раньше любой провал обнулял калибровку целиком, а в «Памяти»
  оставлялось около двух секунд — пройти её было почти невозможно.
- **Коды доступа — вне репозитория (v6.0)**: в GitHub **нет ни одного хеша
  и ни одного пароля**. Коды живут в `auth.local.json` (файл вне git) и
  подставляются в сборку сайта — на GitHub Pages из секрета `AUTH_LOCAL_B64`,
  на своём хостинге — при `npm run build`. Формат — PBKDF2-HMAC-SHA256
  (соль + 150 000 итераций): офлайн-перебор опубликованного хеша непрактичен.
  Старый sha256 больше не принимается из исходников. Подробно — `docs/AUTH.md`.
- **Политики вмешательства (v6.0)**: авто-пауза при нарушении во время
  испытания, «мягкий режим» (нарушения пишутся, но не штрафуются), авто-отчёт
  в конце обзвона, лимит попыток входа, напоминание о расписании. Задаются в
  `config.json` (для всех) или прямо в админке (для этого устройства).
- **Журнал угроз (v6.0)**: попытки взлома (неверные коды), подмена сохранённого
  состояния, вмешательство в код, удаление элементов страницы и расхождение
  отпечатка файлов — отдельным списком в админке.
- **Контроль файлов на сервере (v6.0)**: `integrity.json` — опубликованный
  отпечаток кода; сайт сверяет его с тем, что реально загрузилось, и сообщает,
  если файлы на сервере изменили.
- **Горячие клавиши куратора (v6.0)**: <b>Пробел</b> — пауза/продолжить,
  <b>E</b> — завершить, <b>R</b> — отчёт, <b>A</b> — админка.
- **Подпись отчёта (v6.0)**: в JSON-отчёте есть `sha256` тела — видно, что
  отчёт не правили; в отчёте также есть журнал действий и список угроз.
- **Свой секрет на устройство (v6.0)**: подпись сохранённого состояния сессии
  больше не выводится из кода куратора (он был в публичном репозитории) —
  теперь у каждого устройства свой случайный секрет.
- **Два разных кода и разные права (v5.0)**: у **куратора** и у **тех. администратора**
  теперь РАЗНЫЕ коды. Куратор ведёт обзвон (старт, пауза, итог, отчёт). Тех. администратор
  — надзор: живое состояние системы, журнал действий, сводные отчёты, состояние
  автоподдержки, смена своего кода, удалённая конфигурация. Код куратора в админку
  не подходит — это проверено автотестом.
- **Коды хранятся по PBKDF2 (v5.0)**: соль + 150 000 итераций (собственная реализация
  SHA-256/HMAC/PBKDF2 внутри проекта — работает и без сети). Даже если опубликованный
  хеш попадёт к кому-то, перебор кода становится непрактичным. Смена кода администратора
  прямо из админки (действует в этом браузере) + готовые строки для `CONFIG`.
- **Надзор и журнал действий (v5.0)**: в админке — живая таблица состояния (сессия,
  метрики, монитор, целостность кода и страницы, сторож, версия, память) и журнал
  действий: кто вошёл, запустил, вмешался, применил обновление.
- **Сайт сам добавляет возможности (v5.0)**: `config.json` на сервере — настройки
  (порог, калибровка, простой), переключатели функций (строгий режим, автообновление,
  сбор данных об устройстве), объявления и новости. Сайт читает файл сам и применяет
  изменения без обновления кода.
- **Автоподдержка на GitHub (v5.0)**: CI сам проверяет проект (`npm test`), чинит
  известные сбои (`tools/doctor.js --fix`), поднимает версию и раскладывает её по всем
  файлам (`tools/bump.js`), пишет `status.json` — тех. администратор видит в админке,
  что автоподдержка жива. Если проверки не прошли — открывается задача на GitHub.
- **Закрытые дыры (v5.0)**: восстановление сессии после перезагрузки больше **не
  выдаёт права куратора**; обход калибровки по клику на логотип доступен **только
  администратору**; счётчики неудачных попыток разведены по входам (участник не может
  «залочить» куратора); состояние монитора наружу отдаётся **копией** (счётчики не
  подчистить из консоли); данные истории экранируются (нет выполнения чужого кода),
  CSV защищён от формул; опасные методы публичного API закрыты кодом администратора.
- **Своя страница без GitHub (v4.9)**: команда `npm run build` собирает готовый
  к загрузке комплект: папку `dist/` (сайт файлами) и **один файл**
  `dist/index.single.html` (352 КБ — весь сайт в одном файле: стили, скрипты и
  логотип внутри). Плюс архив `obzvon-site.zip` для панели хостинга.
  Внешних зависимостей нет вообще: ни CDN, ни шрифтов, ни аналитики — сайт
  работает на любом статическом хостинге, на своём сервере и даже с флешки.
  Механизм обновлений проверяет `version.json` **на вашем домене**, а не на
  GitHub, — то есть после переноса сайт обновляется сам по вашим релизам.
- **Фоновое обновление без перезагрузки (v4.2)**: когда появляется новая версия,
  сайт обновляет **сам себя прямо в работающей странице** — старый код освобождает
  ресурсы (таймеры, слушатели, модули), новые модули подгружаются с меткой
  времени (обход кэша браузера) и страница продолжает работать. Обзвон **не
  прерывается**: состояние сессии сохраняется и восстанавливается, перезагрузка
  не наказывается. Если идёт испытание — обновление ждёт его конца.
  Заметки к релизу публикуются в `version.json` и показываются в баннере.
- **История обновлений (v4.3–4.4)**: сайт запоминает, какие версии он
  применял и когда; список виден в админке — по нему видно, что фоновое
  обновление реально прошло на живом сайте.
- **Сдержанная анимация (v4.8)**: движение вернулось, но спокойное —
  медленное «дыхание» фона, тонкая линия под топбаром, мягкий блик по кромке
  панелей, живая точка на графике, лёгкий подъём карточек при наведении.
  Никакого мигания: все эффекты долгие (3–26 с) и низкоконтрастные,
  а при «меньше движения» страница полностью статична.
- **Спокойный интерфейс (v4.6)**: убраны «новогодние» эффекты — вращающиеся
  неоновые рамки панелей, скан-лучи, аврора, меш-пятна, CRT-развёртка, дождь
  цифровых глифов, искры при клике и след за курсором. Остались редкие
  мерцающие звёзды. Палитра сведена к одному акценту, типографика и цифры
  выровнены, карточки метрик приведены к единому виду.
- **Админка (v4.2)**: пункт меню «Админка» (🔒) открывается по коду куратора.
  Внутри: обновления (проверить / обновить в фоне / закрыть), состояние всех
  подсистем с авто-починкой, перезапуск, отчёт о состоянии в JSON, очистка
  хранилища и **локальный нагрузочный тест** (20 000 событий ввода и 1 000
  нарушений прямо в странице — наружу ничего не уходит).
- **Самопочинка и страница «Обслуживание» (v4.1)**: сайт обслуживает себя сам.
  Новая страница «Обслуживание» проверяет все подсистемы (загруженные модули,
  структура DOM, canvas, localStorage, память страницы, состояние сессии,
  отзывчивость монитора, живой график, целостность кода), показывает результат
  по каждой и ведёт **журнал ошибок**. Кнопка «🛠 Восстановить» чинит то, что
  чинится без человека: пересоздаёт график, перезапускает монитор, синхронизирует
  интерфейс с состоянием сессии, переключает работу без localStorage.
  **Сторож** в фоне каждые 5 секунд проверяет, что монитор отвечает и график
  растёт, и сам перезапускает зависшее. Отчёт о состоянии скачивается в JSON.
- **Живая динамика почичена (v4.1)**: график включается с самого начала обзвона
  (включая калибровку), а не только в момент сессии; в шапке панели — текущие
  значения «КОНЦ/ЧИТ» и пульсирующий индикатор LIVE; под графиком — живая лента
  последних событий; при потере canvas график пересоздаётся сам, размер
  подстраивается под окно (ResizeObserver), сетка рисуется всегда.
- **Живая динамика в реальном времени (v4.0)**: на странице «Сеанс» рисуется
  график концентрации и «читомеряка» по ходу обзвона (canvas, обновление раз в
  секунду). На графике отмечаются верные и проваленные испытания, а также
  нарушения (штриховые линии). Под графиком — сводка: средняя, пик, минимум,
  максимальный «читомеряк» и число замеров.
- **История обзвонов и сравнение (v4.0)**: отдельная страница «История» —
  все завершённые обзвоны с вердиктом, концентрацией, «читомеряком», реакцией
  и числом испытаний. Карточки сводки (всего, средняя, лучший, худший, зачёты),
  столбчатая диаграмма по обзвонам, сравнение выбранного обзвона с предыдущим
  (Δ по каждому показателю) и экспорт в CSV.
- **Обновление сайта (v4.0)**: вместо просьбы «нажмите Ctrl+F5» — настоящая
  кнопка «⟳» в топбаре и баннер обновления с кнопками «Обновить сейчас» и
  «Позже». Если обзвон не идёт — страница обновляется сама (с отсчётом),
  если идёт — обновление применяется сразу после его завершения, обзвон при
  этом не прерывается. Проверка новой версии выполняется каждую минуту.
- **Защита v4.0**: детект автотестов и ботов (Playwright, Puppeteer, Selenium,
  `navigator.webdriver`, headless-браузеры), перехват захвата экрана через
  WebRTC (`getDisplayMedia`), детект страницы во второй вкладке, детект подмены
  системных часов (`Date.now`), детект паузы-отладчика (открытые DevTools),
  подпись сохранённых данных сессии (правка `localStorage` со штрафом),
  проверка целостности DOM (удаление водяного знака или служебных блоков),
  расширенный список блокируемых сочетаний клавиш (Ctrl+T, Ctrl+W, Ctrl+Tab,
  Ctrl+±, Ctrl+0 и др.), блокировка печати.
- **Экспорт и импорт статистики (v3.8)**: в «Результатах» кнопки **«Экспорт»**
  и **«Импорт»** — общую статистику (число обзвонов, средняя, история, фишки)
  можно сохранить в JSON-файл и восстановить из него, например после очистки
  браузера или на другом компьютере.
- **Сортировка таблиц результатов (v3.8)**: клик по заголовку столбца любой
  из двух таблиц (метрики и журнал испытаний) сортирует её по этому столбцу,
  повторный клик меняет направление; активный столбец подсвечен стрелкой ▲/▼.
- **Страница «Справка» (v3.8)**: отдельный раздел в боковой панели — как проходит
  обзвон, все виды испытаний, клавиши и ввод, советы участникам, разбор разделов
  «Результаты/статистика» и краткое описание защиты.
- **Отдельные страницы под каждый раздел**: боковая панель-навигация слева
  (Сеанс, Пульт куратора, Система, Память, Результаты, История, Журнал, Новости,
  Справка) переключает страницы вместо прокрутки; при старте сессии и при каждом
  новом испытании система сама возвращает на страницу «Сеанс», после итогов — на
  «Результаты».
  Липкий топбар с таймером сессии и статусом, адаптив — на узких экранах панель
  превращается в шторку по кнопке ☰.
- **Страница «Память»**: общий объём ОЗУ ПК, занятая и выделенная память
  JS-heap с полосой загрузки и лимитом страницы, размер данных localStorage,
  занятое сайтом место на диске и квота браузера, живой график JS-heap
  за последние 60 замеров (каждые 3 с). Браузер не даёт веб-странице доступа
  к общему использованию ОЗУ операционной системы — это ограничение
  безопасности, поэтому показываются только данные, доступные странице.
- **Живой космический фон** (`js/fx.js`): мерцающие звёзды с глубиной и параллаксом
  от курсора, редкие падающие звёзды, аврора-лучи, неоновые глифы-дождь,
  виньетка и анимированное зерно плёнки.
- **Анимированный градиент-фон (v3.6)**: под страницей плавно перетекают
  четыре неоновых пятна-меша (пурпурный, голубой, фиолетовый, зелёный) —
  дышат, вращаются и смещаются поверх звёзд; слой лёгкий (только transform),
  уважает «меньше движения».
- **Страница «Новости разработчика» (v3.7)**: отдельный раздел в боковой панели
  с таймлайном изменений — версии, даты и описания обновлений; у свежей
  версии пульсирующий золотой бейдж.
- **Защита v3.8**: во время сессии на фоне страницы отображается невидимый
  **водяной знак с ID сессии** — любой снимок экрана сразу покажет, чья
  это сессия; система периодически **проверяет целостность кода** и реагирует
  на попытки вмешательства; набор блокируемых сочетаний клавиш расширен.
- **Расширенная графика (v3.7)**: искры при клике по странице (неоновые
  частицы с гравитацией на canvas), глитч RGB-сдвига и свечение кнопок
  при наведении, живой блик и пульс метки на активном пункте меню.
- **Новая графика v4.0**: неоновый след за курсором, импульсные волны при
  нарушениях, полноэкранная вспышка при блокировке, пульс метки версии,
  когда доступно обновление.
- **Неон/киберпанк v3.1**: вращающиеся градиентные рамки панелей, скан-луч,
  редкий глитч-сдвиг заголовка, 3D-наклон карточек по курсору, CRT-развёртка,
  пурпурный источник света.
- **Стеклянные панели** с каскадным вступлением секций; учтена настройка
  «меньше движения» (prefers-reduced-motion) — фон статичен.
- **Кнопки** с объёмом, бликом при наведении и эффектом нажатия.
- **Испытания**: арена с перспективной сеткой-полом, пульсирующая цель,
  Струп с физической «толщиной» кнопок.
- **Итоги**: карточка с вращающейся градиентной рамкой, вердикт влетает
  с размытием, фишки сияют бликом по очереди; если за сеанс верно пройдены
  все шесть видов испытаний — «Полный набор».
- **Фишки анти-списывания (v3.4–3.5)**: отдельные достижения за чистое поведение
  на обзвоне — «Руки прочь», «Буфер под защитой», «Снимки отбиты», «Без следов»,
  «Клавиши отбиты», «Стальной корпус»; у них фирменная графика — вращающаяся
  неоновая рамка и свечение. Таймауты испытаний увеличены в 1,5 раза — на ответ
  даётся больше времени.
- **Фишки v4.0**: «Без телеметрии» (ни захватов экрана, ни автотестов),
  «Кирпичная стена» (10+ отбитых сочетаний клавиш), «Один экран»
  (второго монитора не было), «Целостность» (данные сессии под подписью).

## Как публикуется сайт (v6.0)
С v6.0 сайт публикуется **из сборки**, а не прямо из ветки — иначе в готовом
сайте не было бы кодов доступа (в репозитории их нет).

| Площадка | Как | Где берутся коды |
|---|---|---|
| **GitHub Pages** | workflow «Публикация ОБЗВОН» собирает `dist/` и выкладывает | из секрета `AUTH_LOCAL_B64` |
| **Свой хостинг** | `npm run build` → залить `dist/` или `obzvon-site.zip` | из локального `auth.local.json` |
| **Один файл** | `dist/index.single.html` положить как `index.html` | коды встроены внутрь |

> Переключение Pages на публикацию из сборки:
> `gh api -X PUT repos/<владелец>/<репозиторий>/pages -F build_type=workflow`
> (или Settings → Pages → Source: GitHub Actions).

Секрет с кодами создаётся один раз:
```
base64 -w0 auth.local.json > auth.b64        # Windows: [Convert]::ToBase64String([IO.File]::ReadAllBytes("auth.local.json"))
gh secret set AUTH_LOCAL_B64 --body "$(cat auth.b64)"
```

## Запуск и своя страница

**Локально:** просто откройте `index.html` в браузере (файл `file://`) — всё работает,
кроме автопроверки обновлений (она включается только при раздаче по http).

**Сборка для размещения:**

```
npm install        # один раз (нужен только для тестов и сборки)
npm run build      # -> dist/ + dist/index.single.html + obzvon-site.zip
npm run serve      # локально отдать собранный сайт: http://127.0.0.1:8080
```

**Куда положить (любой из вариантов — ничего не зависит от GitHub):**

1. **Панель хостинга** (Timeweb, Beget, Selectel, Hostinger, Netlify, Vercel, Cloudflare
   Pages и любой другой): загрузить `obzvon-site.zip` и распаковать в корень сайта.
2. **Один файл:** загрузить `dist/index.single.html` как `index.html` — сайт целиком
   в одном файле, ничего больше не нужно.
3. **Свой сервер (nginx / Apache):** скопировать содержимое `dist/` в корень сайта.
   Минимальный конфиг nginx:

   ```nginx
   server {
       listen 80;
       server_name example.ru www.example.ru;
       root /var/www/obzvon;      # сюда положить содержимое dist/
       index index.html;
       location / { try_files $uri $uri/ /index.html; }
       location = /version.json { add_header Cache-Control "no-store"; }
   }
   ```

   `version.json` отдавать без кэша — тогда обновления подхватываются сразу.
4. **Свой компьютер в локальной сети:** `npm run serve` и раздать адрес
   `http://<ip-компьютера>:8080`.

После переноса проверка новых версий идёт по **вашему** домену: положите рядом
новый `version.json` с новым `"v"` — и сайт обновится сам, в фоне, без
перезагрузки страницы и без обрыва обзвона.

## Роли и надзор
В системе две роли с **разными кодами**:

| Роль | Код | Что может |
|---|---|---|
| **Куратор** | свой | пульт обзвона: старт, пауза, завершение, отчёт, сброс, порог доверия |
| **Тех. администратор** | свой | всё, что у куратора, **плюс** админка: надзор, журнал действий, сводный отчёт, обновления, смена кода, конфигурация |

Код куратора **не открывает админку**. В пульте есть две кнопки входа — «Войти · куратор»
и «Войти · админ»; в админке — только код тех. администратора.

### Статистика посещений (v6.1)
В админке есть блок **«СТАТИСТИКА (В ЦИФРАХ)»**: открытия сайта, участники,
калибровки (начато/пройдено), обзвоны (начато/завершено), первый и последний
визит.

Это счётчики **этого браузера**. Чтобы видеть общие числа по всем, кто заходил
на сайт с разных устройств, нужен сборщик на сервере:
```
1) скопируйте tools/collect.php рядом с index.html (тот же домен!);
2) в config.json укажите:
     "collect": { "url": "collect.php" }
3) перезагрузите сайт — сборщик начнёт считать.
```
Без PHP — запустите `node tools/collector.js 8080` и укажите его адрес.
Что передаётся: случайный id устройства, тип события (`visit`, `calib.start`,
`calib.pass`, `session.start`, `session.end`) и время. Никаких личных данных.

### Как задать и сменить код
С v6.0 коды задаются **вне репозитория** (файл `auth.local.json`):
```
node tools/passgen.js --emit --admin --code "КОД ТЕХ. АДМИНИСТРАТОРА"
node tools/passgen.js --emit --curator --code "КОД КУРАТОРА"
node tools/passgen.js --show            # что настроено
node tools/passgen.js --check "КОД"     # проверить
```
Полная инструкция — `docs/AUTH.md`.
```
node tools/passgen.js "НОВЫЙ КОД"              # строки для CONFIG (куратор)
node tools/passgen.js "НОВЫЙ КОД" --admin      # строки для CONFIG (тех. администратор)
node tools/passgen.js --check "КОД"            # проверить, что код записан верно
```
Строки вставляются в `CONFIG` файла `js/app.js` (`passHash/passSalt/passIter` —
куратор, `adminHash/adminSalt/adminIter` — тех. администратор).

Сменить код **тех. администратора** можно прямо в админке («ДОСТУП И РОЛИ»): новый код
сохраняется в этом браузере (соль + PBKDF2), а рядом появляются готовые строки для
`CONFIG` — вставьте их в файл, чтобы код действовал на всех устройствах.

> Код держите в тайне. Хеш лежит в публичном репозитории — без соли его можно перебрать,
> поэтому используйте PBKDF2 и длинный код.

## Самообслуживание и админка
«Админка» (🛠 в боковом меню, вход **по коду тех. администратора**) — панель
механика для самой системы. Система сама:

- проверяет свои подсистемы каждые 30 секунд и показывает, что живо, а что нет;
- ведёт журнал ошибок (в том числе необработанных отказов и ошибок скриптов);
- чинит то, что чинится: пересоздаёт «мёртвый» график, перезапускает зависший
  монитор, возвращает интерфейс в соответствие с состоянием сессии;
- сторож (отдельный фоновый таймер) поднимает монитор и график, если они
  перестали отвечать прямо во время обзвона;
- выгружает полный отчёт о состоянии в JSON;
- применяет новые версии **в фоне**, без перезагрузки страницы и без обрыва
  обзвона (чистый перезапуск модулей + обход кэша браузера);
- проводит локальный нагрузочный тест и показывает, сколько времени заняла
  обработка десятков тысяч событий.

Если подсистему починить нельзя (например, не загрузился модуль или страница
вставлена во фрейм) — система прямо пишет, что нужно перезагрузить страницу.

## Автоподдержка на GitHub (CI)
В `.github/workflows/` лежат два сценария — сайт обслуживается без участия человека.

**`self-maintain.yml`** — ежедневно и при каждом пуше в `main`:
1. `node tools/doctor.js` — статическая диагностика (версия, разметка, CSP, секреты, роли);
2. `npm test` — автотесты (smoke, e2e, security, roles, load, build);
3. `node tools/bump.js --bump patch` — версия поднимается и расходится по всем файлам
   (`version.json`, `js/app.js`, `js/monitor.js`, `index.html`, `README.md`, `config.json`),
   в новости добавляется запись о релизе;
4. `node tools/status.js` — пишется `status.json` (тех. администратор видит его в админке);
5. коммит и тег `vX.Y` от имени `obzvon-bot`;
6. если проверки не прошли — на GitHub открывается (или дополняется) задача с логом.

Токен для коммитов — встроенный `GITHUB_TOKEN` (право `contents: write`), в код сайта
он не попадает никогда. Сайт при этом обновляется **по вашему домену** (по `version.json`),
а не по GitHub — то есть после переноса на свой хостинг обновления продолжат работать.

**`pages.yml`** — публикация на GitHub Pages (если Pages включены в настройках
репозитория; иначе шаг публикации молча пропускается).

### Удалённая конфигурация
`config.json` лежит рядом с `index.html` и читается сайтом **самим**: правки файла на
сервере подхватываются без обновления кода. Поддерживаются:

| Ключ | Что делает |
|---|---|
| `threshold` | порог доверия (10–100) |
| `calibCount` | испытаний калибровки (6/10/20/50/100) |
| `idleLimit` | время простоя до штрафа, мс |
| `features.autoUpdate` | сайт сам применяет новую версию |
| `features.strict` | строгий режим: блокируются дополнительные сочетания клавиш |
| `features.collectDevice` | собирать ли данные об устройстве в отчёте |
| `banner` | объявление на странице при загрузке |
| `news` | массив новостей `{v, title, text}` — появятся в разделе «Новости» |

## Как проводить обзвон
1. **Участник сам** нажимает **«▶ Начать обзвон»** в гейте — обзвон стартует
   **сразу, без кода куратора и без калибровки** (v7.9). Куратор может войти
   в «ПУЛЬТ КУРАТОРА» по коду, чтобы видеть метрики и управлять сеансом
   (пауза, завершение, отчёт). Код на самой странице не показывается.
2. Калибровка с v7.9 **убрана из интерфейса** (кнопка в гейте и настройка в
   пульте скрыты) — осталась только внутренней настройкой темпа. Количество
   испытаний задаётся конфигурацией: **6 / 10 / 20 / 50 / 100**. При 6 — по одному каждого
   вида (случайный порядок): клавиша, цель, удержание, математика, память,
   Струп; при 10+ виды чередуются случайно.
3. Во время обзвона испытания появляются каждые **4–8 секунд** (v7.11: темп
   ускорён, долгого ожидания нет; «Спринт» — 2.5–5.5 с, «Тренировка» — 6–12 с).
   Виды испытаний:
   - **Клавиша** — нажать указанную клавишу (работает при любой раскладке);
   - **Цель** — кликнуть по движущейся цели;
   - **Удержание** — держать пробел до конца отсчёта;
   - **Математика** — решить пример в уме и ввести ответ цифрами;
   - **Память** — запомнить символы и ввести их по порядку;
   - **Струп** — кликнуть по кнопке того цвета, КОТОРЫМ написано слово
     (цвет слова обманывает — это настоящий Струп).

   Число символов, примеры и скорость подбираются автоматически и со временем
   становятся жёстче — точные значения не раскрываются.
4. Куратор смотрит на «ЧИТОМЕРЯК» у участника (участник демонстрирует экран) и
   по кнопке **«Завершить»** получает вердикт: ЗАЧЁТ / СОМНИТЕЛЬНО / НЕЗАЧЁТ.
5. **«Отчёт»** скачивает JSON со всеми метриками, журналом, списком испытаний
   и фишками.

## Таблица результатов (всё на странице)
Раздел **«ТАБЛИЦА РЕЗУЛЬТАТОВ»** обновляется в реальном времени:
- **левая таблица** — метрики: концентрация, читомеряк, фокус, смены вкладок, срывы фокуса,
  лишние экраны, провалы испытаний, простой, копирование, DevTools, перезагрузки, средняя
  реакция, число нарушений;
- **правая таблица** — журнал каждого испытания: номер, вид (тег КАЛИБР/СЕАНС), итог
  (ВЕРНО/ПРОВАЛ + причина) и время реакции в мс;
- сверху сводка: «N испыт. · верно K · ср. реакция X мс».
Журнал переживает закрытие итогов (виден до нового обзвона) и попадает в JSON-отчёт.

## Пауза и завершение участником
Во время обзвона у участника есть панель: **«⏸ Пауза»** (переключается в «▶ Продолжить»)
и **«■ Завершить обзвон»** (с подтверждением). После завершения показываются итоговая
таблица и **фишки** — достижения за обзвон:
- ⚡ СКОРОСТНОЙ, 🎯 ТОЧНЫЙ, 🛡 ЖЕЛЕЗНЫЙ ФОКУС, ✨ ЧИСТЫЙ ЛИСТ, 🏃 МАРАФОН, 🔥 РАСКУСОТКА,
  😌 СПОКОЙСТВИЕ, 💪 БОЕВОЙ ДУХ, 🔗 СЕРИЯ, 🧠 ФОТОПАМЯТЬ, 🎨 СТРУП-МАСТЕР, 🔢 ЧИСЛОВОЙ ГУРУ,
  ⌨️ МАСТЕР КЛАВИШ, 🧊 ЛЁД, 💎 ИДЕАЛЬНЫЙ, 🥇 ЧЕМПИОН, 🛠 ЧИСТАЯ КАЛИБРОВКА, 🔁 ВОЗВРАЩЕНИЕ,
  🏅 ВЕТЕРАН.
Фишки копятся в общей статистике и попадают в отчёт.

## Журнал событий
Раздел **«ЖУРНАЛ СОБЫТИЙ»** пишет всё подряд, новое сверху: старт/пауза/продолжение
обзвона, каждое испытание с результатом и реакцией, нарушения со штрафами, блокировки,
разблокировки, перезагрузки и итог с вердиктом. Во время сессии журнал сохраняется —
переживает перезагрузку страницы (восстанавливается вместе с сессией).

## Как считается концентрация
`Концентрация = фокус (35%) + скорость реакции к личной базе (30%) + (100 − читомеряк) (35%)`

- **Фокус** — доля времени, проведённого на странице во время обзвона;
- **Реакция** — среднее время ответа относительно базы, замеренной на калибровке
  (быстрее базы — не выше 100%, медленнее — падает). Честный замер: у «удержания»
  вычитается сам интервал удержания, у «памяти» — время показа;
- **Читомеряк** — штрафы за нарушения (конкретные веса не раскрываются).

Концентрация и читомеряк обновляются мгновенно: любое нарушение подсвечивает карточку
метрики красной вспышкой.

**Концентрация не сбрасывается** после завершения обзвона и после провала — финальные
цифры остаются на экране до старта нового обзвона. Обнуление происходит только при
нажатии «Начать обзвон» — начинается чистая сессия.

## Средняя концентрация по всем обзвонам
После завершения каждого обзвона его итоговая концентрация добавляется в накопительную
статистику (последние 20 обзвонов) — карточка **«СРЕДНЯЯ КОНЦЕНТРАЦИЯ»** показывает среднее
и динамику к прошлому разу (▲ рост / ▼ падение). Данные хранятся в браузере участника
(`localStorage`); после перезагрузки страницы сохраняются. Средняя попадает в итоговую
таблицу и в JSON-отчёт.

## Что засчитывается как нарушение
Система фиксирует события внимательности участника и начисляет за них штрафы —
конкретный перечень весов и порогов закрыт и в открытых материалах не публикуется.
По умолчанию фиксируются, в том числе: уход со вкладки и потеря фокуса, провал
испытания, открытие DevTools, использование второго экрана, перезагрузка страницы,
снимки экрана, копирование, длительный простой, изменение масштаба.

При превышении порога участника **блокирует** — снимает куратор кодом.
Счётчик «читомеряка» при этом НЕ обнуляется.

## Работа с телефона
Все испытания проходятся и с телефона/планшета: **кнопки ответа расположены сразу под
заданием** (листать не нужно — страница сама подкручивает испытание в крат): буквы и
цифры нажимаются тачем, «удержание» делается большой кнопкой «УДЕРЖИВАЙТЕ» (нажать и
держать пальцем — дрожание пальца не сбрасывает), цель и Струп — обычным тапом. Пустая
арена при этом не занимает место. Физическая клавиатура на десктопе работает как раньше.

## Настройка
### Инструменты v6.0
```
npm run doctor        # диагностика (в т.ч. «в репозитории нет хешей кодов»)
npm run doctor:fix    # диагностика + авто-починка известных сбоев
npm run bump:patch    # поднять версию и разнести по файлам
npm run integrity     # пересчитать отпечаток файлов (integrity.json)
npm run passgen -- --show            # состояние кодов
npm run passgen -- --emit --admin --code "КОД"
npm run inject:auth  # внедрить коды в dist/ (обычно делает build)
```
### Коды доступа
- **куратор** — `passHash` / `passSalt` / `passIter` в `CONFIG` (js/app.js);
- **тех. администратор** — `adminHash` / `adminSalt` / `adminIter`;
- сгенерировать: `node tools/passgen.js "КОД"` и `node tools/passgen.js "КОД" --admin`;
- проверить: `node tools/passgen.js --check "КОД"`;
- сменить код администратора без правки файла — прямо в админке.

### Прочее
Файл `js/app.js`, блок `CONFIG` в начале:
- `threshold` — порог блокировки (можно менять и из панели куратора);
- `calibCount` — число испытаний калибровки по умолчанию (сейчас `100`);
- `idleLimit` — время простоя до штрафа.

Код куратора: как его задать — инструкция хранится локально у автора и в открытые
материалы не выносится. Сам код на странице и в публичных файлах не содержится.

Название сообщества — в `index.html`, заголовок `<h1>`.
Логотип — файл `assets/logo.svg` (замените на свой).
