# Коды доступа ОБЗВОН v6.0 — как задать и как спрятать

С v6.0 коды доступа **не лежат в репозитории**. В репозитории нет ни хешей,
ни паролей — только код самого сайта. Это важно: репозиторий публичный, и любой
хеш из него можно перебрать офлайн.

---

## Как это устроено

```
auth.local.json          ← источник правды: хеши кодов (соль + PBKDF2)
      │  (локальный файл, в git НЕ попадает)
      ├──► js/auth.local.js  ← то, что читает браузер (тоже вне git)
      └──► (в CI) секрет AUTH_LOCAL_B64 → сборка сайта на Pages
```

Порядок, в котором сайт ищет код роли:

1. **localStorage этого устройства** — если код меняли прямо в админке;
2. **`window.OBZ_AUTH`** — файл `js/auth.local.js`, подставленный при сборке;
3. **`CONFIG`** — только если автор вписал вручную (в репозитории это пусто).

Формат кода — **PBKDF2-HMAC-SHA256**: соль (16 случайных байт) + 150 000 итераций.
Старый формат (sha256 без соли) принимается только из файла вне репозитория
и только пока код не перевыпущен: такой хеш перебирают за секунды.

---

## Разово: задать коды

```bash
# код тех. администратора
node tools/passgen.js --emit --admin --code "ВАШ КОД"

# код куратора
node tools/passgen.js --emit --curator --code "ВАШ КОД"

# что сейчас настроено (хеши не показываются)
node tools/passgen.js --show

# проверить, что код сохранён верно
node tools/passgen.js --check "ВАШ КОД" --admin
```

После этого в проекте появятся два файла (оба вне репозитория):

| Файл | Назначение | В git? |
|---|---|---|
| `auth.local.json` | источник правды: хеши, соль, итерации | **нет** |
| `js/auth.local.js` | файл, который читает браузер | **нет** |

`.gitignore` содержит оба имени, а `npm run doctor` проверяет, что они
не отслеживаются git и что в исходниках нет хешей.

## Сборка и публикация

### Локально (свой хостинг)

```bash
npm run build
```

Сборка сама внедряет `js/auth.local.js` в `dist/` (в том числе в однофайловую
версию `dist/index.single.html`). Готовую папку `dist/` или архив
`obzvon-site.zip` заливаете на хостинг как раньше.

> Если на сервере нет `js/auth.local.js` — входа в пульт и админку не будет.
> Это осознанно: без файла с кодами публичный сайт никто не войдёт.

### GitHub Pages

Сайт публикуется **из сборки**, а не из ветки — иначе в артефакте не было бы
кодов. Секрет с кодами хранится в GitHub Actions:

```bash
# один раз: положить auth.local.json в секрет репозитория
base64 -w0 auth.local.json   # Windows: [Convert]::ToBase64String([IO.File]::ReadAllBytes("auth.local.json"))
gh secret set AUTH_LOCAL_B64 --body "<base64>"
```

Секрет `AUTH_LOCAL_B64` читает `.github/workflows/pages.yml` на этапе сборки —
в репозитории он не появляется, но в собранном сайте коды работают.

## Смена кода

### В админке (быстро, только это устройство)

«Админка» → «ДОСТУП И РОЛИ» → «Сменить код». Новый код сохраняется в
localStorage этого браузера (соль + PBKDF2) и действует сразу. Рядом появляются
готовые строки для `auth.local.json` — вставьте их туда, чтобы код работал
на всех устройствах, и пересоберите сайт.

### Через файл (для всех устройств)

```bash
node tools/passgen.js --emit --admin --code "НОВЫЙ КОД"
npm run build
# и залить обновлённый auth.local.json в секрет AUTH_LOCAL_B64
```

### Откат к коду из файла

Кнопка «↺ Код из репозитория» в админке убирает локальное переопределение.

## Что ещё закрыто в v6.0

| Что | Как |
|---|---|
| Хеш кода в публичном репозитории | хеши только в `auth.local.json` вне git |
| Перебор кода по хешу | PBKDF2: соль + 150 000 итераций |
| Старый sha256-хеш | принимается только из файла вне репозитория и помечается в админке как слабый |
| Подделка состояния сессии | секрет подписи теперь **свой на каждое устройство** (`obzvon_v2_secret` в localStorage), а не выводится из кода |
| Правка файлов на сервере | `integrity.json` — опубликованный отпечаток кода; сайт сверяет его с загруженным |
| Утечка через отчёт | отчёт содержит `sha256` тела — правка видна |
| Секреты в исходниках | `npm run doctor` проверяет, что хешей нет и что файлы с кодами не отслеживаются git |

## Честно о границах

Сайт статический: код доступа проверяется **в браузере**, на машине участника.
Это значит:

- участник может открыть исходники страницы и посмотреть, как устроена проверка —
  это невозможно спрятать в статике;
- поэтому единственная настоящая защита — **длинный код** (PBKDF2 делает
  офлайн-перебор непрактичным) и отсутствие хеша в публичном репозитории;
- если нужен настоящий контроль (кто именно вошёл, с какого устройства, в какое
  время) — нужен сервер: проверка кода на нём, а не в браузере. Тогда код вообще
  не появляется на устройстве участника.

Что система уже делает сама: фиксирует все попытки входа, подмену состояния,
вмешательство в код и расхождение отпечатка — всё это видно тех. администратору
в блоке «УГРОЗЫ».
