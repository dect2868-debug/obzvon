# Тех. администратор ОБЗВОН — инструкция

Документ для того, кто ведёт систему: как войти, что видно в админке, как вмешаться
и как сделать так, чтобы сайт сам себя обслуживал.

---

## 1. Два кода, две роли

| Роль | Где входит | Что может |
|---|---|---|
| **Куратор** | «Пульт куратора» → «Войти · куратор» | старт/пауза/завершение обзвона, отчёт, сброс, порог доверия (с v7.9 участник может начать обзвон и сам, без кода) |
| **Тех. администратор** | «Админка» (🛠) или «Войти · админ» в пульте | всё, что у куратора, **плюс** надзор, журнал действий, сводный отчёт, обновления, смена кода, конфигурация |

Коды **разные**. Код куратора в админку не подходит — это проверяется автотестом
(`tests/roles.js`).

### Коды и репозиторий (v6.0)
В GitHub **нет ни хешей, ни паролей** — коды лежат в `auth.local.json` вне
репозитория и подставляются в сборку сайта. Подробно — `docs/AUTH.md`.
Проверить, что всё настроено: `node tools/passgen.js --show`.
В админке в блоке «ДОСТУП И РОЛИ» видно, настроен ли код на этом хостинге
и не выдан ли он в старом формате (sha256) — такой код надо перевыпустить.

### Первичный код администратора

Код, заданный в репозитории (в `CONFIG` файла `js/app.js`), — **стартовый**.
Репозиторий публичный, значит и хеш публичный: стартовый код смените сразу
после первого входа (раздел 3).

### Хранение кодов

В коде лежит только хеш. Варианты:

| Формат | Поля в `CONFIG` | Надёжность |
|---|---|---|
| sha256 (старый) | `passHash` | перебор по опубликованному хешу возможен — только для очень длинного кода |
| **PBKDF2 (рекомендуется)** | `passHash` + `passSalt` + `passIter` | перебор практически невозможен |

Сгенерировать и проверить:

```bash
node tools/passgen.js "КОД"              # строки для CONFIG (куратор)
node tools/passgen.js "КОД" --admin      # строки для CONFIG (тех. администратор)
node tools/passgen.js --check "КОД"      # сверить код с текущим CONFIG
node tools/passgen.js --check "КОД" --admin
```

Соль и итерации считаются **внутри проекта** (собственная реализация
SHA-256/HMAC/PBKDF2 в `js/app.js`) — работает без сети и без внешних библиотек.
Алгоритм сверяется с эталоном Node в автотестах.

## 2. Что видно в админке

### ДОСТУП И РОЛИ
Текущая роль, предупреждение, если код куратора хранится без соли, смена своего кода,
ссылка на «код из репозитория» (откат).

### НАДЗОР
Живая таблица (обновляется раз в секунду):

- **СЕССИЯ** — состояние, ID, длительность;
- **МЕТРИКИ** — концентрация, «читомеряк», число нарушений;
- **МОНИТОР** — смены вкладок, срывы фокуса, экраны, копирования, заблокированные
  клавиши, перезагрузки;
- **ИСПЫТАНИЯ** — журнал, провалы, средняя реакция;
- **ЦЕЛОСТНОСТЬ** — состояние подписи сессии и структуры страницы;
- **СТОРОЖ** — сколько проверок и починок;
- **ВЕРСИЯ** — установлена и доступна;
- **ПАМЯТЬ** — объём страницы и localStorage.

### АВТОПОДДЕРЖКА И КОНФИГУРАЦИЯ
- **status.json** — результат последнего прогона CI на GitHub (когда, какая версия,
  какой коммит);
- **config.json** — что применено из удалённой конфигурации.

### ЖУРНАЛ ДЕЙСТВИЙ
Кто вошёл, запустил, вмешался, применил обновление, сменил код, сбросил хранилище.
Хранится локально (до 200 записей), попадает в сводный отчёт.

### Остальное (из v4.x)
Обновления (проверить / применить в фоне / закрыть), состояние всех подсистем с
авто-починкой, перезапуск, отчёт о состоянии в JSON, очистка хранилища, локальный
нагрузочный тест.

### Сводный отчёт
Кнопка «⬇ Сводный отчёт» в блоке «НАДЗОР» — один JSON со всем: сессия, счётчики
монитора, целостность, сторож, обновления, статус сборки, конфигурация, диагностика,
журнал действий, данные устройства.

## 3. Как вмешаться

| Задача | Что сделать |
|---|---|
| Начать/остановить обзвон | участник сам жмёт «▶ Начать обзвон» в гейте (v7.9); куратор — «Пульт куратора» (вход по коду) |
| Снять блокировку участника | окно блокировки → код куратора **или** администратора |
| Обойти калибровку участнику | с v7.9 калибровка скрыта из интерфейса, обходить не нужно; пять кликов по логотипу остались для администратора (механика внутренняя) |
| Применить обновление | «ОБНОВЛЕНИЯ» → «Обновить в фоне» (обзвон не прерывается) |
| Починить подсистему | «СОСТОЯНИЕ СИСТЕМЫ» → «Восстановить» |
| Перезапустить систему | «⟲ Перезапуск» |
| Очистить данные | «🧹 Очистить хранилище» (необратимо) |
| Сменить свой код | «ДОСТУП И РОЛИ» → «Сменить код» |

> Смена кода в админке действует **только в этом браузере**. Чтобы код работал везде —
> вставьте выведенные строки в `CONFIG` файла `js/app.js` и задеплойте.

## 4. Статистика: сколько людей заходило на сайт
В админке — блок **«СТАТИСТИКА (В ЦИФРАХ)»**. По умолчанию это счётчики
**этого браузера**: открытия сайта, участники, калибровки (начато/пройдено),
обзвоны (начато/завершено), первый и последний визит.

Чтобы получить общие числа (со всех устройств), включите сборщик:
1. `tools/collect.php` → положить рядом с `index.html` (тот же домен — иначе
   запрос закроет CSP);
2. в `config.json`: `"collect": { "url": "collect.php" }`;
3. перезагрузить сайт.

Без PHP: `node tools/collector.js 8080` — но такой адрес доступен только вам,
значит сборщик должен стоять на том же хостинге, что и сайт.

Передаётся только анонимное: случайный id устройства, тип события, время.
Админ увидит: «ВСЕГО ЛЮДЕЙ», «ВСЕГО ВИЗИТОВ», «КАЛИБРОВОК (всего)»,
«ОБЗВОНОВ (всего)».

## 5. Сайт сам добавляет возможности: `config.json`

Файл лежит рядом с `index.html` и читается сайтом **самим** (при раздаче по http).
Правки подхватываются без обновления кода.

```json
{
  "app": "obzvon-config",
  "v": "5.0",
  "features": {
    "autoUpdate": true,
    "strict": false,
    "collectDevice": true,
    "audit": true
  },
  "threshold": 60,
  "calibCount": 100,
  "idleLimit": 65000,
  "banner": "Сегодня обзвон в 19:00",
  "news": [
    { "v": "5.0", "title": "Заголовок новости", "text": "Текст новости" }
  ]
}
```

| Ключ | Что делает | Диапазон |
|---|---|---|
| `threshold` | порог доверия | 10–100 |
| `calibCount` | испытаний калибровки | 6 / 10 / 20 / 50 / 100 |
| `idleLimit` | простой до штрафа, мс | от 10 000 |
| `features.autoUpdate` | сайт сам применяет новую версию | true/false |
| `features.strict` | строгий режим (доп. блокировка клавиш) | true/false |
| `features.collectDevice` | собирать данные устройства в отчёте | true/false |
| `features.audit` | вести журнал действий | true/false |
| `banner` | объявление при загрузке страницы | строка |
| `news` | новости в разделе «Новости» | массив |

Ключи, которых нет в списке, игнорируются — файл не может сломать страницу.

## 6. Автоподдержка на GitHub

### Что происходит без вас

`.github/workflows/self-maintain.yml` (ежедневно и при каждом пуше в `main`):

1. `node tools/doctor.js` — статическая диагностика;
2. `npm test` — 89 проверок (статика, сценарии, защита, роли, нагрузка, сборка);
3. `node tools/bump.js --bump patch` — версия поднимается и расходится по всем файлам;
4. `node tools/status.js` — пишется `status.json` (его видно в админке);
5. коммит и тег `vX.Y` от имени `obzvon-bot`;
6. при сбое — задача на GitHub с логом (или дополняется существующая).

Токен для коммитов — встроенный `GITHUB_TOKEN` (`contents: write`). В коде сайта
он не появляется никогда.

### Ручной запуск

GitHub → Actions → «Самообслуживание ОБЗВОН» → Run workflow → выбор: `patch`,
`minor`, `major`, `none` (только синхронизация версии без подъёма).

### Локально

```bash
npm run doctor        # диагностика
npm run doctor:fix    # диагностика + авто-починка известных сбоев
npm run bump:patch    # поднять версию и разнести по файлам
npm run status ok "описание"   # записать status.json
```

### Как это выглядит в жизни
```
вы правите код  →  push в main  →  CI: тесты + диагностика
                 →  версия +1 и разнесена по всем файлам
                 →  коммит от obzvon-bot + тег vX.Y
                 →  сайт сам подхватывает новую версию (version.json на домене)
                 →  status.json показывает в админке: «ok, версия 5.2»
```
Если тесты упали — релиз не выходит, на GitHub появляется задача с логом, и в
статусе остаётся последняя успешная проверка.

### Чего CI не делает

- не придумывает новые функции — только поддерживает то, что уже написано;
- не чинит код, который не понимает: непонятные сбои попадают в задачу на GitHub;
- не имеет доступа к вашему хостингу: сайт обновляется по `version.json`
  **на вашем домене**, поэтому после переноса на свой хостинг обновления
  продолжат работать.


## 8. Новые блоки v6.0–v7.0
### ПОЛИТИКИ И ВМЕШАТЕЛЬСТВО
Авто-пауза при нарушении, мягкий режим (без штрафов), авто-отчёт в конце,
лимит попыток входа. Значения действуют на этом устройстве; общие — в
`config.json` (раздел `policies`). Кнопка «↺ Сбросить локальные» возвращает
значения из конфигурации.

### УГРОЗЫ
Неверные коды, подмена состояния сессии, вмешательство в код, удаление
элементов страницы. Здесь же — следы попыток взлома.

### ТРЕВОГА (v7.0)
Сильное нарушение во время обзвона поднимает тревогу: яркая плашка вверху
админки, звук и запись в списке. Чтобы получать тревоги в **Telegram**, положите
рядом с `collect.php` файл `telegram.local.json` (в репозитории его быть не
должно — там токен бота):
```json
{ "enabled": true, "token": "123456:ABC...", "chat": "123456789" }
```
и включите сборщик в `config.json`.

### ПРОФИЛИ УЧАСТНИКОВ И ДОВЕРИЕ (v7.0)
Список профилей устройств: обзвонов, концентрация, реакция и оценка доверия
(0–100: 75+ — высокое, 45+ — среднее, ниже — подозрительно). Профиль — это
анонимный отпечаток устройства, не человек.

### НАСТРОЙКИ ИНТЕРФЕЙСА (v7.0)
Плотность, крупные кнопки ответа (удобно на телефоне), громкость звуков.
Сохраняются в браузере участника.

### ПРИМЕР ИСПЫТАНИЯ (v7.0)
Выберите вид и нажмите «👁 Показать» — задание появится на странице «Сеанс».
Удобно проверить, как всё выглядит, не начиная обзвон.

### ГОРЯЧИЕ КЛАВИШИ
Пробел — пауза/продолжить, E — завершить обзвон, R — скачать отчёт,
A — открыть админку. Во время испытания клавиши не перехватываются.

### ОТПЕЧАТОК ФАЙЛОВ
Кнопка «⟳ Проверить файлы» сверяет опубликованный `integrity.json` с тем, что
реально загрузилось. Расхождение = файлы на сервере изменили.

## 9. Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| Код не подходит | `node tools/passgen.js --check "КОД"` — покажет, совпадает ли он с `auth.local.json` |
| Вход не работает на сервере | на сервере нет `js/auth.local.js` — пересоберите (`npm run build`) и залейте |
| «код куратора не настроен на этом хостинге» | на этом сервере нет файла кодов — см. `docs/AUTH.md` |
| В админке «код куратора хранится как простой sha256» | усилите хранение: `node tools/passgen.js "КОД"` и вставьте строки в `CONFIG` |
| В админке нет состояния автоподдержки | CI ещё не отработал или `status.json` не загружен на сервер |
| Сайт не подхватывает `config.json` | проверка идёт только при раздаче по http (не с `file://`) |
| У всех участников счётчики нулевые | сборщик не настроен или стоит на другом домене (его закроет CSP) |
| После обновления страница «поехала» | «⟲ Перезапуск» в админке; если не помогло — Ctrl+F5 |
| Тесты падают в CI | посмотрите задачу на GitHub: там лог и состояние версии |
